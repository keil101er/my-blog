# 原子操作

## 读写操作
- __atomic_store_n(ptr,value,param); 原子写
- __atomic_load_n(ptr,param);原子读

## 什么时候需要执行原子操作

| 两边怎么访问 | 具体例子 | 怎么判断 |
|---|---|---|
| 两边都只读 | 主程序和中断都读取固定的 CAN 通道配置 | 两边都不会改变它，通常可以直接读 |
| 一边写，另一边读 | 发送代码依次更新 `read_slot` 和 `used_slots`，中断需要同时读取这两个值 | 中断可能看到“新的读位置 + 旧的槽数”。如果它依赖两者一致，就需要保护 |
| 两边都可能写 | 发送成功要执行 `used_slots -= 3`，bus-off 中断会把 `used_slots` 清零 | 两条路径可能互相打断，必须协调，否则就可能出现前面说的 `0 - 3` 回绕 |





## 内存序
可以把内存序参数理解成插在原子操作旁边的一道“单向栅栏”：

原因：编译器优化（如 -O2）和 CPU 流水线在单线程视角下，为了跑得更快，可能会偷偷调换代码的执行顺序。

| 参数 | 含义 | 适用场景 |
| --- | --- | --- |
| `__ATOMIC_RELAXED` | 无栅栏：只保证这一个变量自身读写是原子的，前后代码随便重排 | 纯计数器（如统计丢包数），不保护别的数据 |
| `__ATOMIC_RELEASE` | 写端栅栏（拦上放下面）：保证它前面的所有读写必须全部完成并对外可见，才能执行这句写 | “数据全准备好 → 发布标志” |
| `__ATOMIC_ACQUIRE` | 读端栅栏（拦下放上面）：保证它后面的所有读写绝对不能提前到这句读之前执行 | “先读标志 → 再安全访问后面的数据” |
