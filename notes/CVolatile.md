# C 语言 volatile：作用与使用边界

**`volatile` 告诉编译器：对象可能因当前代码之外的因素变化，对它的访问必须按实现规定保留。** 它约束相关访问的优化，不是关闭整个程序的优化。

## 它解决什么问题

读取硬件状态寄存器或 ISR 修改的标志时，连续读取可能得到不同结果。编译器不能只因为普通代码没有写入，就一直复用先前读到的值。

```c
static volatile unsigned int irq_flag;
```

`static` 和 `volatile` 可以同时使用：前者控制这里名字的内部链接，后者约束对对象的访问。`volatile` 不会延长局部变量的生命周期。

## 哪些情况适合使用

| 场景 | 使用要点 |
| --- | --- |
| 内存映射外设寄存器 | 通常通过 `volatile` 限定的对象或指针访问，并遵守芯片的访问宽度等规定 |
| ISR 与普通代码共享标志 | 通常需要 `volatile` 防止错误复用旧值，但还要确认访问宽度、原子性和竞争条件 |
| 任务或线程之间共享数据 | **不能仅靠 `volatile` 同步**，应使用锁、原子操作或 RTOS 通信机制 |
| DMA 缓冲区 | **不能仅靠 `volatile` 保证一致性**，还需按芯片要求处理缓存及内存顺序 |

## 三个常见误区

### “每次都从内存读取，所以一定是最新值”

`volatile` 约束编译器，**不保证绕过 CPU Cache，也不负责刷新缓存**。实际访问行为仍由编译器实现、处理器和内存属性决定，不能等同于“即时可见”。

### “加了 volatile，读写就是原子的”

**`count++` 仍然包含读取、计算和写回。** 即使 `count` 有 `volatile`，并发执行仍可能丢失更新；单次读写是否原子也取决于类型、对齐和平台。

### “共享变量、信号量都应加 volatile”

**`volatile` 不提供互斥，也不保证普通数据与标志之间的内存顺序。** 多线程中无同步地并发读写非原子对象，至少一方写入时，仍可能形成数据竞争。

中断和任务之间传递事件时，优先使用 RTOS 的队列、任务通知或信号量接口；不能把一个 `volatile` 变量当成完整的信号量。参见 [FreeRTOS 中断接口](/notes/FreeRTOSFromISR)。

编译器层面的边界见 [GCC 的 volatile 说明](https://gcc.gnu.org/onlinedocs/gcc/Volatiles.html)。
