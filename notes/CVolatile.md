# C 语言 volatile：作用与使用边界

`volatile` 解决的是**编译器可能复用旧值、删除或合并读写**的问题。它用于访问硬件寄存器，或访问会被中断处理程序修改的变量。

## 为什么普通变量可能读不到新值

下面的串口接收标志由中断处理程序设置，主循环等待它变为 1：

```c
volatile unsigned char rx_done = 0;

void USART1_IRQHandler(void)
{
  rx_done = 1;
}

int main(void)
{
  while (rx_done == 0) {
    /* 等待接收完成 */
  }

  /* 处理接收数据 */
}
```

主循环的代码没有给 `rx_done` 赋值。如果没有 `volatile`，编译器可能认为它的值不会改变，只读取一次，然后反复使用这个旧值，循环就可能无法退出。

加上 `volatile` 后，编译器必须保留源码要求的访问。每次判断 `rx_done == 0` 都要重新读取，不能拿之前读到的值代替。

所以，`volatile` 约束的是**编译器怎样生成访问这个变量的代码**。它不是让变量自动变得线程安全，也不是关闭整个程序的优化。

## 访问硬件寄存器也是同样的原因

硬件寄存器的值可能被外设改变，写入寄存器还可能触发硬件动作。例如：

```c
#define UART_STATUS (*(volatile unsigned int *)0x40011000UL)

while ((UART_STATUS & 0x01U) == 0) {
  /* 等待硬件就绪 */
}
```

`UART_STATUS` 看起来是普通变量，实际对应固定地址上的硬件状态。每次循环都要读取当前状态，因此指针必须指向 `volatile` 对象。否则，编译器可能把重复读取优化成一次。

写入硬件寄存器时也一样。连续写两次可能代表两次独立的硬件操作，编译器不能因为它们写的是同一个地址就删掉前一次。

## volatile 不能保证什么

### 不保证读写操作的原子性

即使变量带有 `volatile`，自增操作仍然包含读取、加一、写回。单次读写能否一次完成，也取决于数据宽度、对齐方式和处理器。

例如，当主程序已经完成读取和加一后，此时被中断打断，中断修改完数据后，返回主程序写回数据，这样就会导致中断中的数据更新丢失。

### 不保证多线程同步

`volatile` 不会加锁，也不能保证一个变量与另一个变量之间的访问顺序符合线程通信要求。任务或线程之间传递事件，应使用原子操作、互斥锁，或 RTOS 提供的队列、信号量和任务通知。

### 不负责处理 CPU Cache

`volatile` 不会自动绕过或刷新 Cache。DMA 直接读写内存时，还要按照芯片要求处理缓存一致性和内存顺序，不能只在缓冲区指针上加 `volatile`。

一句话记忆：**`volatile` 让编译器保留对对象的读写；原子性、互斥和缓存一致性要由其他机制保证。**
