# 代码从哪里运行：NOR、NAND 与 XIP

程序运行时，CPU 需要能够按指令地址取指。存储器能否接到可寻址的代码空间、访问粒度是多少，决定了代码能否直接执行。

## NOR 与 NAND 的差别

| 特性 | NOR Flash | NAND Flash |
| --- | --- | --- |
| 读取方式 | 支持按地址随机读取 | 通常按页读取 |
| 编程与擦除 | 编程、擦除粒度依器件而定 | 按页编程、按块擦除 |
| 典型用途 | 存放可直接取指的代码、小容量数据 | 大容量数据存储 |
| 直接执行代码 | 接入合适的存储器接口后可以 | 通常先复制到 RAM 等可执行存储区 |

NAND 并非“只能按块寻址”：页是常见的读取和编程单位，块是擦除单位。它通常不直接支持 CPU 按字节随机取指，所以运行其中的程序前要先搬运代码。常见 MCU 的内部 Flash 多按 NOR 方式组织，可直接用于取指。

## XIP 省去了代码搬运

XIP（Execute In Place）指 CPU 直接从存放代码的非易失性存储器取指，不先把整段代码复制到 RAM。它可以减少代码对 RAM 的占用，也省去启动阶段的复制过程，适合 RAM 有限的系统。

XIP 仍需要满足硬件条件：存储器必须映射到 CPU 可执行地址空间，接口、时钟和存储器协议也要支持相应访问。把文件写入任意 Flash，并不等于它已经能够 XIP。

启动时间和执行速度不能一概而论：

- 省去复制通常有利于启动，但存储器初始化、映射配置和校验仍需要时间。
- 取指速度取决于存储器带宽、接口频率、等待周期、缓存和芯片实现。带缓存的外部 Flash 可能接近内部执行效率，也可能因频繁未命中而明显变慢。
- XIP 区域中的机器码和只读数据可以在执行期间保留在 Flash 中，全局变量、栈和堆仍需放在可写存储区。自修改代码也不适合直接放在只读映射中。

## 两种存储架构只需分清取指与数据访问

冯·诺依曼架构让指令和数据共享存储与访问通路；哈佛架构为两者提供独立通路，可以并行取指和访问数据。这里的差别描述的是访问结构，不直接决定代码存放在 NOR 还是 NAND，也不要求程序与变量必须位于两块完全独立的物理存储器。
