# Cortex-M 函数调用：栈里保存了什么

普通函数调用没有固定的压栈数量。编译器根据函数是否继续调用其他函数、使用了哪些寄存器、局部变量需要多少空间，生成不同的栈操作。

## 函数调用为什么需要栈

执行 `call` 类指令时，LR 保存返回位置。但若这个函数还要调用另一个函数，后一次调用会覆盖 LR，因此原返回地址需要先保存下来。

下面是一个常见形式：

```c
void process(void)
{
  prepare();
  send();
}
```

`process()` 不是叶子函数，因为它还会调用其他函数。编译器可能在函数开头生成：

```asm
PUSH {LR}
BL prepare
BL send
POP {PC}
```

`PUSH {LR}` 保存 `process()` 的返回地址。最后的 `POP {PC}` 取回这个地址并返回调用方。

如果 `process()` 不再调用任何函数，且不需要其他栈空间，它可能完全不压栈。

## 除了返回地址，还可能保存什么

### 需要保留的寄存器

按照常见 ARM AAPCS 调用约定，R0–R3 主要用于参数和返回值，R4–R11 用于保存需要在调用前后保持的值。

函数如果要使用其中某些寄存器，又不能破坏调用方仍在使用的值，就会先把它们压栈。例如：

```asm
PUSH {R4, R5, LR}
```

不同函数用到的寄存器不同，保存数量自然不同。

### 放不进寄存器的局部数据

较小的局部变量可能只使用寄存器，不占栈空间。局部数组、较大的结构体或需要内存地址的变量，通常需要栈空间：

```c
void make_packet(void)
{
  unsigned char header[16];
  fill_header(header);
  send_packet(header);
}
```

编译器可能通过 `SUB SP, SP, #N` 一次划出所需空间，而不是把每个字节分别 `PUSH`。函数返回前再恢复 SP。

### 放不进参数寄存器的参数

常见 AAPCS 下，前几个合适的整数或指针参数通过 R0–R3 传递，更多参数可能需要调用方放在栈上。具体布局还受参数类型和对齐要求影响。

## 一个函数的栈帧由几部分组成

函数执行期间属于它的一段栈空间称为栈帧，可能包含：

- 保存的 LR 和通用寄存器；
- 局部变量及临时计算结果；
- 传给被调用函数的部分参数；
- 为满足对齐要求而留出的空间。

这些部分都不是每个函数必有。编译器、优化等级和函数实现发生变化时，栈帧大小也可能变化。因此，普通函数调用不能像硬件异常栈帧那样，用固定字数推算所有返回地址。

栈的作用也不只是“保存返回地址”：**它为每次函数执行提供独立的临时空间，使局部变量和调用现场能够在函数返回后恢复或释放。**
