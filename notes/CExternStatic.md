# C 语言 extern 与 static：声明、链接和存储期限

**`extern` 常用于引用共享对象；文件级 `static` 让名字只在当前编译单元内关联；局部 `static` 让对象在函数返回后继续存在。** 后两种作用要分开记。

## 先区分三个概念

| 概念 | 关心的问题 |
| --- | --- |
| 作用域 | 在代码的哪些位置可以用这个名字？ |
| 链接属性 | 不同位置声明的名字，是否指向同一个对象或函数？ |
| 存储期限 | 对象的存储空间保留多久？ |

这里的“编译单元”可以近似理解为一个 `.c` 文件连同它包含的头文件。

## extern：声明与定义分开

**声明告诉编译器名字和类型，定义则为对象提供存储，或给出函数体。** `extern` 声明引用的定义可以在别的文件，也可以在当前文件。

下面的声明分别放入对应文件，共享同一个变量：

```c
// counter.h：声明，供使用方包含。
extern int count;
void counter_reset(void);
```

```c
// counter.c：包含自己的头文件，提供定义。
#include "counter.h"
int count = 0;
void counter_reset(void) { count = 0; }
```

```c
// app.c：使用已有定义。
#include "counter.h"
void app_step(void) { ++count; }
```

**兼容的声明可以重复；对需要使用的同一个外部链接对象，整个程序应提供一个定义。** 只有声明却没有所需定义，通常在链接时报错。

| 文件作用域下的写法 | 含义 |
| --- | --- |
| `extern int count;` | 声明，不为它提供定义 |
| `int count = 0;` | 定义 |
| `extern int count = 0;` | **有初始化器，仍是定义**，不宜放入共享头文件 |
| `int count;` | 暂定定义，不应当作共享头文件中的纯声明 |

普通对外函数声明中的 `extern` 通常可以省略。`extern` 也不能把另一个文件中的 `static` 名字变成可直接引用的公共名字。

## static：看它修饰什么

| 用法 | 核心作用 | 没有改变的事 |
| --- | --- | --- |
| 函数内 `static int times;` | **静态存储期限**，整个程序执行期间存在，调用间保留值 | 名字仍是块作用域，只能在相应局部范围使用 |
| 文件级 `static int state;` | **内部链接**，其他编译单元不能通过同名声明引用它 | 文件级变量本来就具有静态存储期限 |
| 文件级 `static void helper(void);` | 函数名具有内部链接，适合模块内部辅助函数 | 不是控制函数“活多久” |

局部静态变量只初始化一次，未显式初始化时默认置零。它不会在函数返回时销毁，但**也不会自动变成线程安全**。

文件级 `static` 限制的是名字的链接；如果主动把对象地址或函数指针传出去，其他模块仍可以通过指针访问或调用。

以上按 C 语言说明，规则可查 [C11 草案 §6.2.2、§6.2.4、§6.9.2](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf)。静态对象的使用见 [静态对象数组与对象池](/notes/CStaticObjectsAndPool)。
