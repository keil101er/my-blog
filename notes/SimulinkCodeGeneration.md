# 从 Simulink 模型到 STM32G4：一次代码生成与集成记录

**生成代码负责计算，MCU 工程负责采样、调用和输出。** 集成时要对齐三件事：输入输出的含义、模型的采样周期、硬件的执行时序。

这里使用 Simulink Coder 生成 FOC 代码，并接入 STM32G4 框架。控制频率为 10 kHz，每 100 μs 计算一次；输入包括三相电流、电角度和母线电压，输出为三相 PWM 比较值。

## 先明确输入输出

| 信号 | 要确认的内容 |
| --- | --- |
| 三相电流 | 输入安培值还是 ADC 计数值；偏置和正方向如何处理 |
| 电角度 | 单位、方向、零点；机械角是否已换算为电角度 |
| 母线电压 | 电压单位及采样比例 |
| 电流给定 | 单位及允许范围 |
| PWM 输出 | 输出占空比还是 CCR；范围是否匹配定时器 |

例如，模型需要电角度时，不能直接传入编码器机械角。数值看起来连续，也可能让 Park 变换算错。

## 模型配置与实际执行一致

- **数据类型**：明确输入、输出和中间量的类型，避免不必要的 `float`、`double` 混用。
- **采样时间**：这套单周期控制模型中的离散 PI、积分器和滤波器按 100 μs 更新。
- **计算量**：优先使用固定尺寸数组，避免控制周期内不必要的动态分配和执行次数不确定的循环。
- **功能分工**：模型处理坐标变换、PI 和 SVPWM；MCU 工程处理 ADC、DMA、编码器与寄存器。

## 一个控制周期怎样执行

典型顺序如下，具体采样点和更新事件由硬件配置决定：

```text
PWM 触发采样
    ↓
ADC/DMA 数据就绪
    ↓
电流偏置与单位换算，读取角度、母线电压和给定值
    ↓
调用一次生成的控制函数
    ↓
写入 CCR，在配置的更新事件统一生效
```

ADC 应在合适的时刻采样，减少开关噪声影响。CCR 使用预装载时，写入值在指定事件生效，便于同步更新三相 PWM。

**100 μs 是整个周期的时间预算。** 采样处理、控制计算及其他中断都要计入，编译通过不能证明计算来得及完成。

## 接入后检查什么

| 检查项 | 目的 |
| --- | --- |
| 启动控制前调用初始化函数 | 为积分器、延时等状态设置初值 |
| 各周期保留 PI 和观测器状态 | 避免每次调用都重新开始计算 |
| 保存同一时刻的输入数据 | 避免中断更新到一半时读取 |
| 观察 $i_d,i_q$、PI 输出和占空比 | 比较模型与 MCU 的计算结果 |
| 测量执行时间，检查输出限幅 | 确认满足周期要求且输出有效 |
