# EtherCAT：从报文寻址到周期通信

EtherCAT 是一种一主多从的工业以太网技术。理解它，可以先抓住两个问题：**报文中的字节怎样到达从站，以及从站软件怎样知道这些字节代表什么。** 前者由寻址和 ESC 硬件处理，后者由应用层的数据定义与映射约定解决。

## 帧怎样经过所有从站

以常见的线型连接为例：

```text
主站 → 从站 1 → 从站 2 → 从站 3
主站 ← 从站 1 ← 从站 2 ← 从站 3（末端折返）
```

主站发出以太网帧，从站的 ESC（EtherCAT Slave Controller）在帧经过时直接提取或插入数据，不必等 MCU 收齐整帧再转发。末端的 ESC 通过端口回环机制让帧沿全双工链路返回，物理上不需要额外接一根回程网线。

可以把帧想成经过多个站点的列车，但“车厢”与从站并非一一对应：**一个子报文可以访问一个从站，也可以交换多个从站的数据。** 数据量或调度需要时，一个周期可以发送多帧，不能把“一帧带走全部数据”当成硬性规则。

主站通常可使用标准以太网控制器，实时性还取决于主站软件、驱动和任务调度。从站需要 ESC 功能，可以由专用芯片、集成器件或 FPGA 实现；采用 MCU + ESC 时，MCU 通过 SPI、并行总线等 PDI（过程数据接口）访问 ESC。

## 帧格式

| 标准以太网帧头 |   EtherCAT帧头  |子报文段(由多个子报文组成) | 标准以太网帧尾 |
| ----------- |  -------------  |---------------------- | ----------- |
| 目的MAC地址(无用)+源MAC地址+类型字段 | 所有子报文长度和 | 子报文头+数据区+子报文尾(WKC计数器) | CRC校验码 |
|             6B+6B+2B             |      2B       |       10B+N+2B(单个子报文)       |    4B    |

- 类型字段：0x0800为IP协议包，0x0806为ARP协议包，0x88A4才是EtherCAT包。
- 子报文头：指令+地址+数据长度，指令由寻址方式：AP(位置)、FP(站点)、L(逻辑)+读写方式：WR(只写)、RD(只读)、RW(读写)组合。

### WKC计数器

每个 子报文 都有独立的 WKC（Working Counter，工作计数器），主站通常从 0 开始，根据命令和预期参与设备计算返回值。下表的读写方向以主站访问从站为准。

| 命令类型 | 成功操作 | 单个从站的 WKC 增量 |
| --- | --- | --- |
| 只读，如 FPRD、LRD | 读成功 | +1 |
| 只写，如 FPWR、LWR | 写成功 | +1 |
| 读写，如 LRW | 仅读成功 / 仅写成功 / 两者成功 | +1 / +2 / +3 |

因此结合命令和WCK值，**主站可以判断从站是否正常完成读写** 

## 三种常用寻址方式

### 位置寻址：启动时按顺序找到设备

APRD、APWR 等命令使用自增寻址。访问第 N 个从站时，初始位置字段填 `1 - N`，按 16 位补码编码；每个从站检查收到的位置字段是否为 0，并将其加 1 后继续传递。

例如找第三个从站：初始值为 `-2`（`0xFFFE`），经过前两个从站后变为 0，第三个从站因此匹配。匹配后仍继续自增。

扫描时，主站也可以对所有设备都支持的 ESC 寄存器执行广播读 `BRD`，通过 WKC 估计响应数量，再逐个读取信息。**广播是单独的一类命令，不是“地址填 0 的位置寻址”，命令名也不是 BPRD。**

### 站点寻址：访问指定从站

主站可用位置寻址将站点地址写入从站的 Configured Station Address 寄存器，随后通过 FPRD、FPWR 等命令访问“站点地址 + ESC 内部地址”。地址由主站分配，不是从站根据距离自动生成。

只访问从站 2 时，不需要给其他从站准备空子报文。帧仍经过它们，但不匹配的设备不执行该数据访问。相关命令和地址字段见 [Beckhoff ESC 技术手册第 2 章](https://download.beckhoff.com/download/document/io/ethercat-development-products/ethercat_esc_datasheet_sec1_technology_2i3.pdf)。

### 逻辑寻址：一次交换多个从站的过程数据

主站给过程数据分配逻辑地址，再配置各从站的 FMMU（现场总线内存管理单元），将逻辑范围映射到 ESC 的内部存储区。运行时，LRD、LWR、LRW 根据起始逻辑地址和长度访问这些范围。

逻辑地址是协议中的 32 位地址，**不是主站或 MCU 的真实指针，也不要求主站分配完整的 4 GB 内存。** 主站软件维护实际使用的过程数据映像，再负责与报文交换数据。

通常在启动时确定 PDO 布局，运行期间保持稳定；但从站判断的是逻辑地址与访问方向，不要求相关字节永远位于整帧的同一个绝对偏移。

## FMMU 与 SyncManager：地址映射和缓冲管理

FMMU 解决“报文中的哪段数据对应 ESC 的哪里”，SM（SyncManager）解决“EtherCAT 侧和本地应用如何一致地访问这块数据”。

| 模块 | 主要配置 | 作用 |
| --- | --- | --- |
| FMMU | 逻辑起始地址、长度与位边界、ESC 内部起点、读写使能、激活状态 | 按逻辑范围和方向映射数据 |
| SM | ESC 缓冲区起点、长度、方向、工作模式、事件及看门狗相关设置、使能 | 管理双方访问与数据一致性 |

常见 CoE 从站使用 SM0 接收主站邮箱消息、SM1 返回邮箱消息、SM2 接收输出过程数据、SM3 提供输入过程数据。本文沿用这套布局，具体数量和用途仍以设备描述为准；FMMU0、FMMU1 的编号也不天然等于收、发方向。

邮箱通常使用单缓冲握手，避免未读消息被覆盖；过程数据常用三缓冲，使一侧写入时另一侧仍能读取完整数据，优先提供最新值，不保证每个历史样本都被消费。详见 [ETG 协议图中的 FMMU 与 SyncManager](https://www.ethercat.org.cn/download/documents/EtherCAT_Device_Protocol_Poster.pdf)。

以从站接收 10 字节为例，数据路径可以是：

```text
报文逻辑地址 0x0000～0x0009
    → FMMU 写映射
    → ESC 内部 0x1100 起的 SM2 缓冲区
    → MCU 通过 PDI 读取
    → 按 PDO 布局更新应用变量
```

`0x1100` 只是示例地址。配置缓冲区时还要按 ESC 的模式预留实际占用空间，三缓冲不能只按单份数据长度规划内存。

这种硬件处理可以类比 DMA，但它不会自动把数据送到任意 MCU 全局变量。外置 ESC 场景下，MCU 通常仍需通过 PDI 读写数据，并遵守完整缓冲区访问规则。

## CoE、对象字典与 PDO 映射

### 字节的含义由谁决定

CoE（CANopen over EtherCAT）复用 CANopen 的对象字典和通信机制。对象字典通过 `16 位索引 : 8 位子索引` 标识参数，并描述类型、权限及 PDO 映射能力。

例如在 CiA 402 驱动器中，`0x6040:00` 表示控制字，`0x6064:00` 表示实际位置。具体对象仍需查设备手册；并非所有 EtherCAT 设备都使用 CoE，也不是所有内部变量都必须暴露到对象字典。

从站软件可以用描述表把索引关联到变量指针或访问回调。SDO 写对象时，通常修改的是对应变量或调用相应操作，不是在改描述表中的索引、类型或指针。PDO 映射对象本身也属于可被描述、访问的参数。

### SDO 与 PDO 

| 对比项 | SDO（服务数据对象） | PDO（过程数据对象） |
| --- | --- | --- |
| 主要用途 | 参数设置、诊断、读取对象 | 周期控制与反馈 |
| 数据定位 | 请求携带对象索引、子索引 | 按预先约定的布局传值 |
| 通道 | 邮箱请求与响应 | 过程数据缓冲区 |
| MCU 工作 | 解析请求、检查权限、准备响应 | 按确定的布局更新应用数据 |

**RxPDO、TxPDO 以从站为视角**：RxPDO 是从站接收、主站输出；TxPDO 是从站发送、主站输入。

### 映射表和分配表是两层关系

以一个 RxPDO 携带“16 位控制字 + 32 位目标位置”为例：

| 对象条目 | 值 | 含义 |
| --- | --- | --- |
| `0x1600:00` | `2` | 此映射有两个有效条目 |
| `0x1600:01` | `0x60400010` | `0x6040:00`，16 bit |
| `0x1600:02` | `0x607A0020` | `0x607A:00`，32 bit |
| `0x1C12:00` | `1` | SM2 分配一个 PDO |
| `0x1C12:01` | `0x1600` | 使用上述 RxPDO |

这张表表示最终配置，不是逐项写入的执行顺序。映射项的 32 位编码为：

```text
索引（16 bit） | 子索引（8 bit） | 映射位长（8 bit）
```

位长用于确定传输布局和后续偏移，并供设备校验。对象字典虽然有类型信息，映射描述仍需明确占用多少位；不能任意填写与设备规则不符的长度。

RxPDO 映射对象常用 `0x1600～0x17FF`，TxPDO 常用 `0x1A00～0x1BFF`。在本文布局下，`0x1C12` 分配 RxPDO，`0x1C13` 分配 TxPDO；多个 PDO 按分配顺序及各自映射顺序形成过程数据布局。**分配表既选择启用哪些 PDO，也决定顺序，不只是开关。**

从站固件决定支持哪些对象、哪些映射可选或可修改，主站在能力范围内配置。支持重映射时，通常在 PREOP 中先禁用相关分配或清零条目数，再写条目、恢复数量，具体顺序按设备要求执行。固定映射设备不一定接受这些写操作。

配置变更还必须同步更新 SM 长度、FMMU 和主站偏移，不能只改映射表就沿用旧布局。运行中需要调整时，通常退回允许配置的状态后重新建立一致配置。

## SDO 为什么需要后续回复

读取 `0x6064:00` 时，索引位于 子报文 数据区所承载的 CoE 请求中：

```text
子报文 头：站点地址 + 邮箱缓冲区的 ESC 内部地址
└─ 数据区
   └─ Mailbox 头
      └─ CoE 头
         └─ SDO 请求：命令、0x6064、0x00 等
```

外层地址由 ESC 处理，将消息送入邮箱；内层索引由从站 CoE 协议栈解释，定位对象字典数据。**SDO 的对象索引不等于 ESC 的寄存器地址。**

一次典型读取过程是：

1. 主站将请求写入从站接收邮箱。
2. MCU 读取并解析请求，检查对象和访问权限。
3. MCU 将结果或 SDO Abort 错误放入发送邮箱。
4. 主站通过后续 EtherCAT 访问取走响应。


## 从上电到 OP：配置从哪里来

| 信息来源 | 主要用途 |
| --- | --- |
| ESI XML 文件 | 厂家提供给主站工具的设备描述，包括身份、PDO、邮箱和同步能力等 |
| 从站 SII，通常存于 EEPROM | 主站在线识别设备、读取基础配置；也可由设备仿真实现 |
| ESC 寄存器、CoE 在线访问 | 获取硬件能力、当前映射及可访问参数 |
| 主站工程或程序 | 确定期望设备、周期、控制模式、启用的 PDO 和逻辑地址布局 |

### EtherCAT 状态机

| 状态 | 可以做什么 | 进入下一阶段前的关键工作 |
| --- | --- | --- |
| INIT | 访问 ESC、识别设备 | 分配站点地址，建立邮箱配置 |
| PREOP | 邮箱可用，可通过 SDO 访问对象 | 确定 PDO，配置过程数据 SM、FMMU，按需配置同步 |
| SAFEOP | 输入过程数据可更新，输出通常保持设备规定的安全状态 | 建立周期交换，提供有效输出数据 |
| OP | 正常输入、输出过程数据交换 | 持续监测通信与设备状态 |

主站请求状态转换，从站检查条件后确认；请求成功发出不等于状态已经到达。失败时应读取实际 AL 状态和状态码。SAFEOP 的输出行为取决于设备及设置，不能将它等同于功能安全保证。状态与转换条件见 [Beckhoff：EtherCAT State Machine](https://infosys.beckhoff.com/content/1033/ek1322/1036980875.html)。

这里还要区分两种配置路径：修改 `0x1600`、`0x1C12` 等 CoE 对象通常通过 SDO；配置 FMMU、SM 的硬件参数则访问 ESC 寄存器。

## 用三台电机串起一个周期

沿用每台电机“主站发送 10 B、接收 6 B”的例子，假设设备支持所选映射，并采用互不重叠的逻辑地址：

| 从站 | RxPDO：主站输出，10 B | TxPDO：主站输入，6 B |
| --- | --- | --- |
| 电机 1 | `0x0000～0x0009` | `0x000A～0x000F` |
| 电机 2 | `0x0010～0x0019` | `0x001A～0x001F` |
| 电机 3 | `0x0020～0x0029` | `0x002A～0x002F` |

每台的 10 B 可以由控制字、目标位置、目标速度组成，6 B 由状态字、实际位置组成。

完成 PDO、SM、FMMU 配置后，若设备支持且主站采用一个覆盖上述范围的 LRW，数据区就是 48 B。三个从站各完成一次读、写贡献，期望 WKC 为 `3 × 3 = 9`；若拆成多个命令，应分别计算。

在这套布局中，从站只读取自己的 10 B 输出段，并在自己的 6 B 输入段填入已准备好的反馈，不会把目标位置直接覆盖成实际位置。收发逻辑地址也可以按其他方案组织；逻辑地址是否重叠，与主站是否使用同一个收发内存缓冲区是两个问题。

### MCU 不会让经过的帧停下来等计算

```text
主站更新输出映像并发帧
    → ESC 接收对应输出，同时提供已准备好的输入
    → 帧返回主站，主站处理反馈并检查 WKC

从站应用按约定的事件或周期运行
    → MCU 读取完整 RxPDO
    → 更新控制与采样结果
    → 将新的 TxPDO 写入 ESC，供之后的访问读取
```

反馈属于哪个采样时刻、相对指令延迟多少周期，取决于同步模式和应用调度，不能默认返回帧已经包含 MCU 针对本次指令计算的结果。

### 通信快还需要动作同步

DC（Distributed Clocks，分布式时钟）用于同步支持该功能的从站本地时钟，并补偿传播延迟和时钟漂移。设备可据此产生 SYNC0/SYNC1 事件，在约定时刻采样或更新输出，而不是单纯依赖帧到达时刻。**SM 保证数据访问一致性，DC 提供共同时间基准。**

SYNC0 是配置产生的定时事件，不等同于“收到一帧”的中断。主站仍需在应用使用数据之前及时送达数据，DC 不会消除 MCU 计算与调度耗时。见 [Beckhoff：Distributed Clocks](https://infosys.beckhoff.com/content/1033/ethercatsystem/2469118347.html)。
